Blender Studio benchmark

Blender Studio benchmark

Blender Studio made better pictures, but it was not always cheaper or faster. A blind judge preferred its picture in 6 of 7 pairs and plain Blender's in 0, with 1 tie. It helped the weaker models most. For Claude Sonnet 5.5 it cost 2.4 times as much and took 2.4 times as long, for a small gain in quality.

The same model was given the same one-line request twice: once with plain Blender (it writes Python, renders, and looks at the result), and once with Blender Studio's tools. 7 such pairs were run, one attempt each.

  • Quality went up, from a low base. The judge's average score rose from 3.5 to 5.1 out of 10. No picture from either way scored above 7, so "better" here does not yet mean "good".
  • Claude Haiku 4.5 gained the most. Its average went from 1.5 to 4.0. On its own its three pictures scored 1, 1 and 2.5. With the tools it was also cheaper ($0.39 against $0.54) and wrote 39% fewer tokens.
  • Claude Sonnet 5.5 barely needed the help. It writes working Blender code first time, finishing each request in under 35 seconds. The tools lifted its score from 5.5 to 6.7, but it read 8.7 times as many tokens, mostly because the descriptions of all 43 tools are sent again with every request.
  • Fewer calls failed. 16 of 120 calls failed with plain Blender (13%), against 10 of 204 with the tools (5%). Plain failures were mostly Python that named commands or settings this Blender version does not have.
  • The tools add their own ways to go wrong. Haiku's mug is hidden behind a huge blob. It left out the handle's thickness, and the tool's default thickness is as big as the mug. That was a defect in my tool. I fixed it after this run and replaying Haiku's exact calls now gives a normal handle, but the score here is the original.

Run by run

Plain Blender Blender Studio

How it was run

  • Plain Blender means three tools: list the scene, run Python inside Blender, and render the camera view. It starts from Blender's default scene. This is my own minimal stand-in for how AI models normally drive Blender, not the blender-mcp package.
  • Blender Studio means the full 43-tool set, including its own run-Python tool, starting from an empty scene.
  • Both ways got the same system prompt, the same request, the same turn limit and the same size of picture back. Claude models ran through the Claude command line with nothing else loaded; both ways ran at the same time on this Mac. Gemini ran through its API with your key, limited to 9 turns by the free daily allowance.
  • The judge was Claude Opus 5.5, which took no part in building. It saw each pair twice under neutral file names, once each way round, and did not know which picture came from which way.
  • "Tokens read" counts everything sent to the model across all its requests, including repeats it reads from cache, so it is far larger than what was newly sent.

What this does not show

  • One attempt per pair. Models vary from run to run, and a handful of pairs is a small sample; a repeat could move any single number a lot.
  • Three simple still-life requests. Nothing here tests animation, people, physics or larger scenes.
  • The judge is a Claude model scoring pictures mostly made by Claude models, and it is one judge. Where it disagreed with itself I counted a tie.
  • Gemini has one pair only. Gemini 3.5 Flash had no free allowance left, and Gemini 3.8 Flash kept timing out. In the pair that ran, the free allowance cut the Blender Studio side off after 8 of its 9 turns.
  • Total time includes rendering, which depends on settings the model picked. One plain-Blender run spent 27 minutes, nearly all of it rendering, before hitting its turn limit; it dominates Haiku's plain total.
  • I built Blender Studio and designed this test. Treat it as a first look, not an independent review.
